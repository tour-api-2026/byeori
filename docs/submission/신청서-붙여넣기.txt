[4] 신청 사유  ─ 전체를 아래로 교체
--------------------------------------------------------------------
벼리는 전국의 관광 명소와 전통 공연·축제를 하나의 지도에서 함께 찾아보고 하루 여행
일정까지 만드는 서비스입니다.

주요 기능은 로컬 저장 없이 요청 시점 실시간 호출로 구현했습니다.

- 지도 주변 탐색 · 명칭 검색 · 지역 탐색
지도가 멈춘 좌표와 반경으로 locationBasedList2를 호출해 이용자가 보고 있는 영역의
장소만 받아옵니다. 전국 데이터를 미리 받아 거르지 않으며, 지도 이동 1회당 1건을
호출합니다. 명칭 검색은 searchKeyword2로, 시·도 지역 탐색은 해당 지역 중심 좌표의
locationBasedList2로 각각 요청 시점에 조회합니다.

- 장소 상세 정보
화면을 열 때 detailCommon2와 detailIntro2를 호출해 소개글·이용시간·휴무일·문의처·
주차 정보를 표시합니다. 저장 목록에 없는 장소도 콘텐츠 ID로 동일하게 조회합니다.
장소 1건당 2건을 호출합니다.

아래 세 항목은 실시간 호출로 대체할 수 없어 사전 수집이 필요합니다.

1. 이용자 관심사 기반 추천
가입 시 선택한 관심사(문화·체험·맛집 등)에 맞춰 전국에서 후보를 선정한 뒤, 자체
보유한 평점과 리뷰 수를 기준으로 정렬해 노출합니다. 정렬 기준이 자체 데이터이므로
API 응답만으로는 순서를 구성할 수 없습니다.

2. 축소된 전국 화면의 장소 표시
locationBasedList2는 반경 상한이 20km입니다. 지도를 전국이 보이도록 축소하면 화면
폭이 200km를 넘어 실시간 호출로는 한가운데만 채워집니다. 이 구간에 한해 저장된
데이터로 화면 전체를 덮고, 20km 이내로 확대하면 다시 실시간 호출로 전환됩니다.

3. 장애 발생 시 서비스 연속성 확보
공사 API 호출이 지연되거나 실패하는 경우 저장된 데이터로 대체하여 화면이 비지 않도록
합니다.

저장 항목은 콘텐츠 ID·명칭·주소·좌표·분류·대표이미지·전화번호로 한정했으며, 소개글·
이용시간 등 변동이 잦은 운영 정보는 저장하지 않고 매번 실시간으로 조회합니다.
2026년 9월 기준 저장 규모는 장소 29,536건, 축제·행사 417건입니다. 데이터 출처는
장소 상세 화면과 마이페이지에 '출처: ⓒ한국관광공사'로 표기하고 있습니다.

상세 내용은 별지를 참조하여 주시기 바랍니다.


[5] 동기화 계획  ─ 전체를 아래로 교체
--------------------------------------------------------------------
동기화 방법
공사에서 로컬 서버 저장용으로 제공하는 areaBasedSyncList2를 사용합니다. modifiedtime
파라미터로 직전 동기화 이후 변경된 콘텐츠만 수신하므로 전체 목록을 매번 내려받지
않습니다. 축제·행사는 searchFestival2로 수집합니다.

수집한 항목은 콘텐츠 ID(contentid)를 기준으로 기존 레코드가 있으면 갱신하고 없으면
추가합니다. 응답의 showflag 값이 0인 콘텐츠는 공사에서 노출을 중단한 것으로 보고 즉시
비노출 처리하여 지도·검색·목록 어디에도 표시되지 않도록 합니다. 2026년 9월 9일
동기화에서 갱신 37건과 비노출 7건을 반영하였습니다.

동기화 주기
1일 1회

동기화 시간
매일 05:00 (KST)
공사의 원본 갱신 시각(04:30) 이후가 되도록 설정했습니다. 그 이전에 수집하면 갱신 전
데이터를 받게 되므로 30분의 여유를 두었습니다.

호출 규모
1회 약 3건. 전체 목록 방식은 약 350건을 호출해야 하나, 변경분만 수신하여 통상 3건으로
완료됩니다. 공사 서버 부하를 고려해 호출 간 120밀리초 간격을 둡니다.

실패 시 처리
실행 결과를 매회 기록하며, 다음 회차의 수집 기준 시점은 마지막으로 성공한 실행일입니다.
특정 회차가 실패하면 기준 시점이 전진하지 않아 다음 회차가 누락된 구간을 함께 수집합니다.

상세 내용은 별지를 참조하여 주시기 바랍니다.
