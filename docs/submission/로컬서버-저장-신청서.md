## 신청 사유

벼리는 전국의 관광 명소와 전통 공연·축제를 하나의 지도에서 함께 찾아보고 하루 여행 일정까지 만드는 서비스입니다.

**주요 기능은 로컬 저장 없이 요청 시점 실시간 호출로 구현했습니다.**

- **지도 주변 탐색** — 지도가 멈춘 좌표와 반경으로 `locationBasedList2`를 호출해 이용자가 보고 있는 영역의 장소만 받아옵니다. 전국 데이터를 미리 받아 거르지 않으며, 지도 이동 1회당 1건을 호출합니다. 좌표는 약 100m, 반경은 500m 단위로 반올림해 같은 화면을 중복 호출하지 않습니다.
- **명칭 키워드 검색** — 이용자가 입력한 검색어로 `searchKeyword2`를 호출합니다. 입력이 멈춘 뒤 0.4초 후 1건을 호출해 타자 중 반복 호출을 막습니다.
- **장소 상세 정보** — 화면을 열 때 `detailCommon2`와 `detailIntro2`를 호출해 소개글·이용시간·휴무일·문의처·주차 정보를 표시합니다. 장소 1건당 2건을 호출합니다.

**아래 세 항목은 좌표나 검색어로 조회할 수 없거나, 공사 API 장애 대비가 필요해 사전 수집이 필요합니다.**

1. **이용자 관심사 기반 추천** — 가입 시 선택한 관심사(문화·체험·맛집 등)에 맞춰 전국에서 후보를 선정한 뒤, 자체 보유한 평점과 리뷰 수를 기준으로 정렬해 노출합니다. 정렬 기준이 자체 데이터이므로 API 응답만으로는 구성할 수 없습니다.
2. **시도·시군구 지역 탐색** — 이용자가 지역을 선택하면 해당 지역의 장소 목록을 즉시 제공합니다.
3. **장애 시 서비스 연속성** — 공사 API 호출이 실패할 경우 저장된 데이터로 대체해 화면이 비지 않도록 합니다.

**저장 항목은 콘텐츠 ID·명칭·주소·좌표·분류·대표이미지·전화번호로 한정했습니다.** 소개글·이용시간·휴무일·주차 등 변동이 잦은 운영 정보는 저장하지 않고, 화면을 열 때마다 공사 API를 실시간으로 조회해 표시합니다.

현재 저장 규모는 장소 29,537건, 축제·행사 417건입니다.

데이터 출처는 장소 상세 화면과 마이페이지의 '데이터 출처' 항목에 `출처: ⓒ한국관광공사`로 표기하고 있으며, API 서비스명 단독 표기는 사용하지 않습니다.

## 동기화 계획

**동기화 방법**

`areaBasedList2`로 관광지(12)·문화시설(14)·음식점(39) 세 유형을 전국 17개 시도별로 페이지를 순회하며 수집하고, 축제·행사는 `searchFestival2`로 수집합니다. 시도 코드는 `ldongCode2`로 조회합니다.

수집한 항목은 콘텐츠 ID(`contentid`)를 기준으로 기존 레코드가 있으면 갱신하고 없으면 추가합니다. 항목 단위로 독립 저장하므로 일부 항목이 실패해도 전체 동기화가 중단되지 않으며, 실패한 항목은 기존 데이터를 유지한 채 다음 회차에 다시 반영됩니다.

**동기화 주기** — 1일 1회

**동기화 시간** — 매일 05:00 (KST)

공사의 원본 갱신 시각(04:30) 이후가 되도록 설정했습니다. 그 이전에 수집하면 갱신 전 데이터를 받게 되므로 30분의 여유를 두었습니다.

**호출 규모** — 1회 약 350건. 공사 서버 부하를 고려해 호출 간 120밀리초 간격을 둡니다.
