## 신청 사유

벼리는 전국의 관광 명소와 전통 공연·축제를 하나의 지도에서 함께 찾아보고 하루 여행 일정까지 만드는 서비스입니다.

**주요 기능은 로컬 저장 없이 요청 시점 실시간 호출로 구현했습니다.**

- **지도 주변 탐색** — 지도가 멈춘 좌표와 반경으로 `locationBasedList2`를 호출해 이용자가 보고 있는 영역의 장소만 받아옵니다. 전국 데이터를 미리 받아 거르지 않으며, 지도 이동 1회당 1건을 호출합니다. 좌표는 약 100m, 반경은 500m 단위로 반올림해 같은 화면을 중복 호출하지 않습니다.
- **명칭 키워드 검색** — 이용자가 입력한 검색어로 `searchKeyword2`를 호출합니다. 입력이 멈춘 뒤 0.4초 후 1건을 호출해 타자 중 반복 호출을 막습니다.
- **시·도 단위 지역 탐색** — 지역을 선택하면 해당 지역 중심 좌표로 `locationBasedList2`를 호출합니다. 지역당 1건입니다.
- **장소 상세 정보** — 화면을 열 때 `detailCommon2`와 `detailIntro2`를 호출해 소개글·이용시간·휴무일·문의처·주차 정보를 표시합니다. 장소 1건당 2건을 호출합니다.

**아래 세 항목은 실시간 호출로 대체할 수 없어 사전 수집이 필요합니다.**

1. **이용자 관심사 기반 추천** — 가입 시 선택한 관심사에 맞춰 전국에서 후보를 선정한 뒤, 자체 보유한 평점과 리뷰 수로 정렬해 노출합니다. 정렬 기준이 자체 데이터라 API 응답만으로는 구성할 수 없습니다.
2. **축소된 전국 화면의 장소 표시** — `locationBasedList2`는 반경 상한이 20km입니다. 지도를 전국이 보이도록 축소하면 화면 폭이 200km를 넘어 실시간으로는 한가운데만 채워집니다. 이 구간에만 저장 데이터로 화면을 덮고, 20km 이내로 확대하면 다시 실시간으로 전환됩니다.
3. **장애 시 서비스 연속성** — 공사 API 호출이 실패할 경우 저장된 데이터로 대체해 화면이 비지 않도록 합니다.

**저장 항목은 콘텐츠 ID·명칭·주소·좌표·분류·대표이미지·전화번호로 한정했습니다.** 소개글·이용시간·휴무일·주차 등 변동이 잦은 운영 정보는 저장하지 않고, 화면을 열 때마다 공사 API를 실시간으로 조회해 표시합니다.

2026년 9월 기준 저장 규모는 장소 29,536건, 축제·행사 417건입니다. 공사에서 노출을 중단한 7건은 비노출 처리되어 서비스에 표시되지 않습니다.

데이터 출처는 장소 상세 화면과 마이페이지의 '데이터 출처' 항목에 `출처: ⓒ한국관광공사`로 표기하고 있으며, API 서비스명 단독 표기는 사용하지 않습니다.

## 동기화 계획

**동기화 주기** — 1일 1회

**동기화 시간** — 매일 05:00 (KST). 공사 원본 갱신 시각(04:30) 이후가 되도록 30분 여유를 두었습니다.

**수집 방법**

공사에서 로컬 서버 저장용으로 제공하는 `areaBasedSyncList2`를 사용합니다. `modifiedtime`으로 직전 동기화 이후 변경분만 수신하므로 전체 목록을 매번 내려받지 않습니다. 축제·행사는 `searchFestival2`로 수집합니다. 수신 항목은 콘텐츠 ID(`contentid`) 기준으로 기존 레코드가 있으면 갱신하고 없으면 추가합니다.

**호출 규모** — 1회 약 3건

전체 목록 방식은 1회 약 350건을 호출해야 하나, 변경분만 수신하면 통상 3건으로 완료됩니다. 공사 서버 부담과 인증키 사용량을 최소화하기 위한 선택입니다.

**삭제·비노출 반영**

응답의 `showflag`가 0인 콘텐츠는 공사에서 노출을 중단한 것으로 보고 즉시 비노출 처리하여 지도·검색·목록에 표시되지 않게 합니다. 이용자의 리뷰·여행 일정이 연결되어 있을 수 있어 레코드는 삭제하지 않고 상태만 변경합니다.

실제로 2026년 9월 9일 동기화에서 갱신 37건과 비노출 7건을 반영했고, 해당 장소가 서비스에서 표시되지 않는 것을 확인했습니다.

**실패 시 처리**

실행 결과를 매회 기록하며, 다음 회차의 수집 기준 시점은 마지막으로 성공한 실행일입니다. 실패하면 기준 시점이 전진하지 않아 다음 회차가 누락 구간을 함께 수집합니다. 장애가 여러 날 이어진 경우 기준 시점을 지정해 일괄 보정할 수 있습니다. 항목 단위로 독립 저장하므로 일부 실패가 전체를 중단시키지 않습니다.
