[별지] 신청 사유 및 동기화 계획

관광 데이터 로컬 서버 저장 신청서 · 서비스명 벼리

1. 서비스 개요

벼리는 전국의 관광 명소와 전통 공연·축제를 하나의 지도에서 함께 찾아보고, 방문할 곳을 담아 하루 여행 일정까지 구성하는 웹 서비스입니다. 전통문화를 접하기 어려운 이유가 콘텐츠의 부족이 아니라 정보가 서로 연결되어 있지 않기 때문이라고 보고, 한국관광공사의 관광 정보와 공연 정보를 하나의 지도 위에 결합하는 것을 목표로 개발했습니다.

2. 실시간 호출 현황

주요 기능은 로컬 저장에 의존하지 않고, 이용자의 요청 시점에 공사 OpenAPI를 직접 호출하는 방식으로 구현했습니다.

기능 호출 오퍼레이션 호출 방식
지도 주변 탐색 locationBasedList2 지도가 멈춘 중심 좌표와 반경으로 호출하여 이용자가 보고 있는 영역의 장소만 조회합니다. 전국 데이터를 미리 받아 걸러내지 않으며, 지도 이동 1회당 1건을 호출합니다. 호출이 실패하는 경우에 한해 저장된 데이터로 대체합니다.

3. 로컬 저장이 필요한 기능

아래 세 항목은 좌표나 검색어를 기준으로 조회할 수 없거나, 공사 API 장애 시의 대비가 필요하여 사전 수집한 데이터가 있어야 합니다.

가. 이용자 관심사 기반 추천

가입 시 선택한 관심사(문화·체험·맛집 등)에 맞추어 전국에서 후보를 선정한 뒤, 자체 보유한 이용자 평점과 리뷰 수를 기준으로 정렬하여 노출합니다. 정렬 기준이 자체 데이터이므로 API 응답만으로는 순서를 구성할 수 없습니다.

나. 시도·시군구 단위 지역 탐색

이용자가 지역을 선택하면 해당 지역의 장소 목록을 즉시 제공합니다. 지도상의 특정 좌표가 아닌 행정구역 전체를 대상으로 하는 탐색입니다.

다. 장애 발생 시 서비스 연속성 확보

공사 API 호출이 지연되거나 실패하는 경우, 저장된 데이터로 대체하여 화면이 비지 않도록 합니다. 대체 표시 항목은 명칭·주소·좌표·분류에 한하며, 실시간으로만 조회하는 운영 정보는 표시하지 않습니다.

4. 저장 범위

저장 항목은 위 기능에 필요한 최소한으로 한정하였으며, 변동이 잦은 운영 정보는 저장하지 않고 매번 실시간으로 조회합니다.

구분 항목 비고
저장 콘텐츠 ID, 명칭, 주소, 좌표, 분류, 대표이미지, 전화번호 목록 표시와 자체 데이터 결합에 필요한 항목
미저장 소개글, 이용시간, 휴무일, 문의처, 주차 정보, 홈페이지 변동이 잦아 상세 화면을 열 때마다 실시간 조회

현재 저장 규모는 장소 29,537건, 축제·행사 417건입니다.

가. 수집 방법

전국 17개 시도별로 콘텐츠 유형 세 가지에 대해 페이지를 순회하며 목록을 수집하고, 축제·행사는 별도로 수집합니다. 수집한 항목은 콘텐츠 ID(contentid)를 기준으로 기존 레코드가 있으면 갱신하고 없으면 추가합니다.

나. 동기화 시간 설정 근거

공사의 원본 데이터 갱신 시각인 04:30 이후가 되도록 05:00으로 설정하였습니다. 그 이전에 수집할 경우 갱신 전 데이터를 받게 되므로 30분의 여유를 두었습니다.

다. 실패 시 처리

항목 단위로 독립하여 저장하므로 일부 항목의 처리가 실패하더라도 전체 동기화가 중단되지 않습니다. 실패한 항목은 기존에 저장된 데이터를 그대로 유지한 채 다음 회차에 다시 반영됩니다. 인증키 미설정 등으로 수집이 불가능한 경우에는 동기화를 수행하지 않고 기존 데이터를 유지합니다.

책임 인지 · 로컬 서버 저장 이후의 콘텐츠 동기화가 신청 기관의 책임으로 진행되어야 하며, 동기화 지연으로 발생하는 문제에 대하여 공사가 책임지지 않음을 확인하였습니다.

6. 출처 표기

장소 상세 화면과 마이페이지의 '데이터 출처' 항목에 출처: ⓒ한국관광공사로 표기하고 있습니다. API 서비스명을 단독으로 표기하는 방식은 사용하지 않습니다.
