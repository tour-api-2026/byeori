[별지] 신청 사유 및 동기화 계획

관광 데이터 로컬 서버 저장 신청서 · 서비스명 벼리

1. 서비스 개요

벼리는 전국의 관광 명소와 전통 공연·축제를 하나의 지도에서 함께 찾아보고, 방문할 곳을 담아 하루 여행 일정까지 구성하는 웹 서비스입니다. 전통문화를 접하기 어려운 이유가 콘텐츠의 부족이 아니라 정보가 서로 연결되어 있지 않기 때문이라고 보고, 한국관광공사의 관광 정보와 공연 정보를 하나의 지도 위에 결합하는 것을 목표로 개발했습니다.

2. 실시간 호출 현황

주요 기능은 로컬 저장에 의존하지 않고, 이용자의 요청 시점에 공사 OpenAPI를 직접 호출하는 방식으로 구현했습니다.

기능 호출 오퍼레이션 호출 방식
지도 주변 탐색 locationBasedList2 지도가 멈춘 중심 좌표와 반경으로 호출하여 이용자가 보고 있는 영역의 장소만 조회합니다. 전국 데이터를 미리 받아 걸러내지 않으며, 지도 이동 1회당 1건을 호출합니다. 호출이 실패하는 경우에 한해 저장된 데이터로 대체합니다.
명칭 키워드 검색 searchKeyword2 이용자가 입력한 검색어로 호출합니다. 입력이 멈춘 뒤 0.4초 후 1건을 호출하여 타자 중 반복 호출을 방지합니다.
시·도 단위 지역 탐색 locationBasedList2 이용자가 지역을 선택하면 해당 지역 중심 좌표로 호출합니다. 지역당 1건을 호출합니다.
장소 상세 정보 detailCommon2

3. 로컬 저장이 필요한 기능

아래 세 항목은 실시간 호출로 대체할 수 없어 사전 수집한 데이터가 필요합니다.

가. 이용자 관심사 기반 추천

가입 시 선택한 관심사(문화·체험·맛집 등)에 맞추어 전국에서 후보를 선정한 뒤, 자체 보유한 이용자 평점과 리뷰 수를 기준으로 정렬하여 노출합니다. 정렬 기준이 자체 데이터이므로 API 응답만으로는 순서를 구성할 수 없습니다.

나. 축소된 전국 화면의 장소 표시

locationBasedList2는 반경 상한이 20km입니다. 지도를 전국이 보이도록 축소하면 화면 폭이 200km를 넘어, 실시간 호출로는 화면 한가운데만 채워지고 나머지가 비어 보입니다. 이 구간에 한해 저장된 데이터로 화면 전체를 덮습니다. 지도를 20km 이내로 확대하면 다시 실시간 호출로 전환됩니다.

다. 장애 발생 시 서비스 연속성 확보

공사 API 호출이 지연되거나 실패하는 경우, 저장된 데이터로 대체하여 화면이 비지 않도록 합니다. 대체 표시 항목은 명칭·주소·좌표·분류에 한하며, 실시간으로만 조회하는 운영 정보는 표시하지 않습니다.

4. 저장 범위

저장 항목은 위 기능에 필요한 최소한으로 한정하였으며, 변동이 잦은 운영 정보는 저장하지 않고 매번 실시간으로 조회합니다.

구분 항목 비고
저장 콘텐츠 ID, 명칭, 주소, 좌표, 분류, 대표이미지, 전화번호 목록 표시와 자체 데이터 결합에 필요한 항목
미저장 소개글, 이용시간, 휴무일, 문의처, 주차 정보, 홈페이지 변동이 잦아 상세 화면을 열 때마다 실시간 조회

현재 저장 규모는 장소 29,543건, 축제·행사 417건입니다.

5. 동기화 계획

항목 내용
주기 1일 1회
시간 매일 05:00 (한국 표준시)
방법 areaBasedSyncList2 — 관광지(12)·문화시설(14)·음식점(39)
searchFestival2 — 축제·행사
규모 1회 약 3건 호출 (직전 동기화 이후 변경분만 수신)

가. 수집 방법

공사에서 로컬 서버 저장용으로 제공하는 areaBasedSyncList2를 사용합니다. modifiedtime 파라미터로 직전 동기화 이후 변경된 콘텐츠만 수신하므로, 전체 목록을 매번 내려받지 않습니다. 수신한 항목은 콘텐츠 ID(contentid)를 기준으로 기존 레코드가 있으면 갱신하고 없으면 추가합니다.

전체 목록을 대상으로 하면 1회에 약 350건을 호출해야 하나, 변경분만 수신하는 방식은 통상 3건으로 완료됩니다. 공사 서버에 대한 부담과 인증키 사용량을 최소화하기 위한 선택입니다.

나. 삭제·비노출 콘텐츠 반영

응답의 showflag 값이 0인 콘텐츠는 공사에서 노출을 중단한 것으로 보고, 저장된 레코드를 즉시 비노출 처리하여 지도·검색·목록 어디에도 표시되지 않도록 합니다. 이용자의 리뷰나 여행 일정이 연결되어 있을 수 있어 레코드 자체는 삭제하지 않고 상태만 변경합니다.

다. 동기화 시간 설정 근거

공사의 원본 데이터 갱신 시각인 04:30 이후가 되도록 05:00으로 설정하였습니다. 그 이전에 수집할 경우 갱신 전 데이터를 받게 되므로 30분의 여유를 두었습니다.

라. 실패 시 처리

동기화 실행 결과를 매회 기록하며, 다음 회차의 수집 기준 시점은 마지막으로 성공한 실행일입니다. 따라서 특정 회차가 실패하면 기준 시점이 전진하지 않아, 다음 회차가 누락된 구간을 함께 수집합니다. 장애가 여러 날 이어진 경우에도 기준 시점을 지정하여 해당 구간을 일괄 보정할 수 있습니다.

항목 단위로 독립하여 저장하므로 일부 항목의 처리가 실패하더라도 전체 동기화가 중단되지 않습니다.

책임 인지 · 로컬 서버 저장 이후의 콘텐츠 동기화가 신청 기관의 책임으로 진행되어야 하며, 동기화 지연으로 발생하는 문제에 대하여 공사가 책임지지 않음을 확인하였습니다.

6. 출처 표기

장소 상세 화면과 마이페이지의 '데이터 출처' 항목에 출처: ⓒ한국관광공사로 표기하고 있습니다. API 서비스명을 단독으로 표기하는 방식은 사용하지 않습니다.
