# 앱 다국어 구현 계획 (1/2 — 앱 쪽)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 앱 화면 전체와 서버 에러 메시지를 한국어·영어·일본어·중국어로 보여주고, 첫 실행 때 언어를 고르고 나중에 바꿀 수 있게 한다.

**Architecture:** 의존성 없는 사전 + `translate()` 로 번역한다(`package.json` 이 바뀌면 OTA 가 끊기므로 패키지를 넣지 않는다). 현재 언어는 zustand 스토어에 두고 기기에 저장한다. 서버 에러는 응답에 이미 있는 `error.code` 로 번역하므로 서버는 손대지 않는다.

**Tech Stack:** TypeScript, React Native (Expo SDK 54), expo-router, zustand, expo-secure-store, axios. 검증은 의존성 없는 `node` 스크립트.

**Spec:** `docs/superpowers/specs/2026-10-20-i18n-design.md`

**범위:** 이 계획은 스펙의 1~3단계(앱 UI + 서버 메시지)만 다룬다. 4~5단계(장소·행사 이름 번역, DB 컬럼, 번역 배치, `Accept-Language` 로 콘텐츠 받기, 검색)는 **별도 계획**이다. 이 계획이 끝나면 앱 화면은 네 언어로 나오고, 장소 이름만 한국어로 남는다.

## Global Constraints

- **`apps/app/package.json` 을 바꾸지 않는다.** 바뀌면 Expo 지문이 달라져 이미 설치된 앱에 OTA 가 닿지 못한다. npm 패키지 추가 금지, 테스트 러너 추가 금지.
- 언어는 네 가지: `ko` · `en` · `ja` · `zh`(중국어 간체). 이 네 값이 `Locale` 타입이고, `Accept-Language` 로도 이 값을 그대로 보낸다.
- 카테고리·지역의 **통신 값은 한국어로 고정한다**(`'문화'`, `'서울'`). 번역하는 것은 표시 라벨뿐이다. DB 마이그레이션도 API 변경도 없다.
- 서버 Java 의 한국어 메시지는 손대지 않는다. 앱이 `error.code` 로 번역하고, 모르는 코드면 서버가 준 `message` 를 그대로 띄운다.
- 사전 키는 화면을 따라 점으로 나눈다(`route.summary`, `routes.empty`).
- 저장소가 막힌 환경(시크릿 모드 등)에서도 앱은 떠야 한다. 저장 실패는 조용히 삼킨다 — `authStore` 의 기존 방식과 같다.
- 모든 검증은 `node apps/app/scripts/i18n-check.mjs` 와 `npx tsc --noEmit` 으로 한다.

## Review Focus

1. **사전에 키가 없을 때** — 선택한 언어에 키가 없으면 한국어로, 한국어에도 없으면 키 문자열 자체가 보여야 한다. 화면이 비면 안 된다. (Task 1)
2. **치환 변수가 빠졌을 때** — `t('x', {})` 처럼 변수를 안 넘기면 `{n}` 이 그대로 보이면 안 되고 빈 문자열이 되어야 한다. (Task 1)
3. **기기 언어가 지원하지 않는 값일 때** — `de-DE`, `fr`, 빈 문자열, `undefined` 가 와도 터지지 않고 "모르겠음"으로 떨어져야 한다. (Task 2)
4. **저장소가 막혔을 때** — `SecureStore` 가 던져도 앱이 떠야 한다. 언어가 저장되지 않아 매번 선택 화면이 뜨는 것은 감수한다. (Task 3)
5. **언어를 바꾼 뒤 이미 받아 둔 서버 데이터** — React Query 가 이전 언어로 받은 응답을 들고 있다. 언어를 바꾸면 캐시를 무효화해야 다음 계획(콘텐츠 번역)에서 장소 이름이 실제로 바뀐다. 지금 넣어 두지 않으면 그때 조용히 안 바뀐다. (Task 4, Task 6)

**Interfaces:**
- Consumes: 없음
- Produces (`locales.ts`, 그리고 `index.ts` 가 재수출한다):
  - `export type Locale = 'ko' | 'en' | 'ja' | 'zh'`
  - `export const LOCALES: readonly Locale[]`
  - `export const LOCALE_NAMES: Record<Locale, string>` — 각 언어의 자기 이름
- Produces (`index.ts`):
  - `export function translate(locale: Locale, key: string, vars?: Record<string, unknown>): string`
- 사전 모듈은 각각 `export const ko: Record<string, string>` 꼴 (파일명과 같은 이름)

**`locales.ts` 를 따로 두는 이유.** `index.ts` 는 나중에 `useT()` 때문에 `localeStore` 를
가져오는데, `localeStore` 와 `device.ts` 는 `Locale`·`LOCALES` 가 필요하다. 한 파일에 두면
`index → localeStore → index` 순환이 생긴다. ES 모듈이 버티기는 하지만 초기화 순서에 따라
`LOCALES` 가 `undefined` 로 보이는 때가 있다. 아무것도 import 하지 않는 파일로 떼어 두면
그 고리가 생기지 않는다.

- [ ] **Step 1: 검사 스크립트를 먼저 쓴다 (실패하는 상태로)**

`apps/app/scripts/i18n-check.mjs`:

```js
// 앱 다국어 검사. 의존성이 없어야 한다 — package.json 이 바뀌면 OTA 가 끊긴다.
//
// 세 가지를 본다.
//   1. 네 사전의 키 집합이 같은지
//   2. translate() 가 키 없음·변수 없음 같은 경우에 어떻게 떨어지는지
//   3. 이미 번역한 화면에 한국어 리터럴이 남아 있지 않은지
//
// 2번은 index.ts 에서 함수 본문을 떼어내 타입 표기만 지우고 실제로 돌린다.
// 베껴 쓰면 구현과 어긋나므로 그렇게 하지 않는다.
import { readFileSync } from 'node:fs';
import { fileURLToPath } from 'node:url';
import { dirname, join } from 'node:path';

const ROOT = join(dirname(fileURLToPath(import.meta.url)), '..');
const I18N = join(ROOT, 'src/lib/i18n');

let failed = 0;
const ok = (label, cond, detail = '') => {
  if (!cond) failed++;
  console.log(`${cond ? 'OK  ' : 'FAIL'} ${label}${cond || !detail ? '' : '  ' + detail}`);
};

// ── 1. 키 집합 ──────────────────────────────────────────────
// 사전은 "'키': '값'," 한 줄 꼴로만 쓴다. 그래야 여기서 읽을 수 있다.
function keysOf(locale) {
  const src = readFileSync(join(I18N, `${locale}.ts`), 'utf8');
  return new Set([...src.matchAll(/^\s*'([^']+)':/gm)].map((m) => m[1]));
}
const LOCALES = ['ko', 'en', 'ja', 'zh'];
const keys = Object.fromEntries(LOCALES.map((l) => [l, keysOf(l)]));
ok('ko 사전이 비어 있지 않다', keys.ko.size > 0, `${keys.ko.size}개`);
for (const l of LOCALES.filter((l) => l !== 'ko')) {
  const missing = [...keys.ko].filter((k) => !keys[l].has(k));
  const extra = [...keys[l]].filter((k) => !keys.ko.has(k));
  ok(`${l} 사전에 빠진 키가 없다`, missing.length === 0, missing.slice(0, 5).join(', '));
  ok(`${l} 사전에 군더더기 키가 없다`, extra.length === 0, extra.slice(0, 5).join(', '));
}

// ── 2. translate() ──────────────────────────────────────────
// index.ts 의 본문을 떼어내 타입 표기만 지운다. 못 찾으면 바로 멈춘다
// (조용히 안 돌면 검사한 척만 하게 된다).
const idx = readFileSync(join(I18N, 'index.ts'), 'utf8');
const SIG = 'export function translate(locale: Locale, key: string, vars?: Record<string, unknown>): string {';
if (!idx.includes(SIG)) {
  console.log('FAIL translate() 서명을 찾지 못했다 — 스크립트의 SIG 를 함께 고칠 것');
  process.exit(1);
}
const body = idx.slice(idx.indexOf(SIG)).replace(SIG, 'function translate(locale, key, vars) {');
const end = body.indexOf('\n}\n');
const fn = new Function('DICT', body.slice(0, end + 3) + '\nreturn translate;');

const DICT = {
  ko: { greet: '안녕 {name}', only: '한국어에만' },
  en: { greet: 'Hi {name}' },
  ja: {}, zh: {},
};
const t = fn(DICT);
ok('치환이 된다', t('en', 'greet', { name: 'Ann' }) === 'Hi Ann');
ok('키가 없으면 한국어로 떨어진다', t('en', 'only') === '한국어에만');
ok('한국어에도 없으면 키를 그대로 준다', t('en', 'nope.key') === 'nope.key');
ok('변수를 안 넘기면 빈 문자열로 치운다', t('en', 'greet') === 'Hi ');
ok('모르는 변수도 빈 문자열', t('ko', 'greet', { other: 1 }) === '안녕 ');

// ── 3. 번역을 마친 화면에 한국어가 남아 있지 않은지 ───────────
// 화면을 옮길 때마다 아래 목록에 더한다. 목록에 없는 파일은 보지 않는다.
const DONE = [
  // 'src/app/(tabs)/routes.tsx',
];
const HANGUL_LITERAL = /(['"`])[^'"`\n]*[가-힣][^'"`\n]*\1/g;
for (const rel of DONE) {
  const src = readFileSync(join(ROOT, rel), 'utf8');
  // 주석 줄은 한국어로 쓴다 — 번역 대상이 아니다.
  const code = src.split('\n').filter((l) => !/^\s*(\/\/|\*|\/\*)/.test(l)).join('\n');
  const hits = [...code.matchAll(HANGUL_LITERAL)].map((m) => m[0]);
  ok(`${rel} 에 한국어 리터럴이 없다`, hits.length === 0, hits.slice(0, 3).join(' | '));
}

console.log(failed ? `\n${failed}건 실패` : '\n전부 통과');
process.exit(failed ? 1 : 0);
```

`apps/app/src/lib/i18n/index.ts`:

```ts
import { ko } from './ko';
import { en } from './en';
import { ja } from './ja';
import { zh } from './zh';
import type { Locale } from './locales';

export { LOCALES, LOCALE_NAMES, type Locale } from './locales';

const DICT: Record<Locale, Record<string, string>> = { ko, en, ja, zh };

/**
 * 문구 하나를 꺼낸다.
 *
 * 떨어지는 차례는 선택한 언어 → 한국어 → 키 자체다. 한국어까지 없을 때 빈 문자열을
 * 주면 버튼에 글자가 사라져 누를 곳이 보이지 않는다. 키가 보이면 흉하지만 고칠 곳을
 * 알려 준다.
 *
 * `{name}` 꼴을 vars 로 치환한다. 넘기지 않은 변수는 빈 문자열이 된다 — 화면에
 * `{name}` 이 그대로 뜨는 것보다 낫다.
 */
export function translate(locale: Locale, key: string, vars?: Record<string, unknown>): string {
  const raw = DICT[locale]?.[key] ?? DICT.ko[key] ?? key;
  return raw.replace(/\{(\w+)\}/g, (_, name) => String(vars?.[name] ?? ''));
}
```

`i18n-check.mjs` 의 `── 3.` 구역 **앞에** 끼워 넣는다:

```js
// ── 2b. normalizeLocale() ───────────────────────────────────
const dev = readFileSync(join(I18N, 'device.ts'), 'utf8');
const NSIG = 'export function normalizeLocale(raw: string | null | undefined): Locale | null {';
if (!dev.includes(NSIG)) {
  console.log('FAIL normalizeLocale() 서명을 찾지 못했다 — 스크립트의 NSIG 를 함께 고칠 것');
  process.exit(1);
}
const nBody = dev.slice(dev.indexOf(NSIG)).replace(NSIG, 'function normalizeLocale(raw) {');
const nEnd = nBody.indexOf('\n}\n');
// LOCALES 는 import 라 본문에 없다 — 넣어 준다. 본문에 타입 캐스트(`as …`)를 쓰면
// node 가 읽지 못하므로 normalizeLocale 은 캐스트 없이 쓴다.
const normalize = new Function('LOCALES', nBody.slice(0, nEnd + 3) + '\nreturn normalizeLocale;')(
  ['ko', 'en', 'ja', 'zh'],
);

ok('ko-KR → ko', normalize('ko-KR') === 'ko');
ok('en-US → en', normalize('en-US') === 'en');
ok('ja_JP → ja (밑줄도 받는다)', normalize('ja_JP') === 'ja');
ok('zh-Hans-CN → zh', normalize('zh-Hans-CN') === 'zh');
ok('zh-TW 도 zh (번체는 따로 두지 않는다)', normalize('zh-TW') === 'zh');
```

```ts
import { NativeModules, Platform } from 'react-native';
import { LOCALES, type Locale } from './locales';   // index 가 아니라 locales — 순환을 피한다

/**
 * 기기가 알려 준 언어 문자열을 우리 네 가지 중 하나로 줄인다.
 *
 * 들어오는 꼴이 제각각이다 — `ko-KR`, `en_US`, `zh-Hans-CN`, `EN`. 앞의 언어 조각만
 * 보고 가른다. 중국어는 간체 하나만 두므로 `zh-TW`(번체)도 `zh` 로 본다. 번체 사용자에게
 * 간체가 보이는 것은 아쉽지만, 한국어가 보이는 것보다는 낫다.
 *
 * 모르는 언어는 null 이다 — 부르는 쪽이 한국어로 떨어뜨린다.
 *
 * 이 함수 본문에는 타입 캐스트(`as …`)를 쓰지 않는다. i18n-check.mjs 가 본문을 떼어내
 * node 로 그대로 돌리는데, 캐스트가 있으면 구문 오류가 난다.
 */
export function normalizeLocale(raw: string | null | undefined): Locale | null {
  if (!raw) return null;
  const head = String(raw).toLowerCase().split(/[-_]/)[0];
  return LOCALES.find((l) => l === head) ?? null;
}

/**
 * 기기 언어를 읽는다. 못 읽으면 null.
 *
 * 패키지를 넣지 않으려고 두 가지 길을 차례로 본다 — `package.json` 이 바뀌면 Expo
 * 지문이 달라져 이미 설치된 앱에 OTA 가 닿지 못한다.
 *
 *   1. Intl — 웹에서는 늘 되고, Hermes 도 대개 지원한다
 *   2. RN 내장 모듈 — Intl 이 없는 빌드를 위한 대비
 *
 * 어느 쪽도 던지지 않게 감싼다. 언어를 못 읽는 것은 앱이 멈출 이유가 아니다.
 */
export function detectDeviceLocale(): Locale | null {
  try {
    const fromIntl = normalizeLocale(Intl?.DateTimeFormat?.().resolvedOptions?.().locale);
    if (fromIntl) return fromIntl;
  } catch {
    // Intl 이 없는 빌드 — 아래로 내려간다
  }
  try {
    const raw =
      Platform.OS === 'ios'
        ? (NativeModules.SettingsManager?.settings?.AppleLocale as string | undefined)
          ?? (NativeModules.SettingsManager?.settings?.AppleLanguages as string[] | undefined)?.[0]
        : (NativeModules.I18nManager?.localeIdentifier as string | undefined);
    return normalizeLocale(raw);
  } catch {
    return null;
  }
}
```

```ts
import { create } from 'zustand';
import { detectDeviceLocale } from '@/lib/i18n/device';
import { LOCALES, type Locale } from '@/lib/i18n/locales';   // index 가 아니라 locales — 순환을 피한다
import { getItem, setItem } from './storage';

const KEY = 'byeori.locale';

type LocaleState = {
  locale: Locale;
  /** 사용자가 직접 고른 적이 있는지. 없으면 첫 실행 언어 화면을 띄운다. */
  chosen: boolean;
  hydrated: boolean;
  setLocale: (l: Locale) => Promise<void>;
  hydrate: () => Promise<void>;
};

export const useLocaleStore = create<LocaleState>((set) => ({
  // 복원 전 기본값. 화면은 hydrated 가 true 가 될 때까지 기다린다.
  locale: 'ko',
  chosen: false,
  hydrated: false,

  setLocale: async (l) => {
    set({ locale: l, chosen: true });
    await setItem(KEY, l);   // 저장이 막혀도 던지지 않는다(storage 가 삼킨다)
  },

  /**
   * 저장된 언어를 되살린다. 없으면 기기 언어로 짐작하되 chosen 은 false 로 둔다 —
   * 짐작은 선택이 아니므로 첫 화면에서 확인받아야 한다.
   */
  hydrate: async () => {
    const raw = await getItem(KEY);
    const saved = LOCALES.find((l) => l === raw);
    if (saved) {
      set({ locale: saved, chosen: true, hydrated: true });
      return;
    }
    set({ locale: detectDeviceLocale() ?? 'ko', chosen: false, hydrated: true });
  },
}));
```

```ts
import { translate } from './index';
import type { Locale } from './locales';
import { useLocaleStore } from '@/lib/store/localeStore';

export type ApiErrorBody = { code?: string; message?: string } | null | undefined;

/**
 * 서버 에러 코드 → 사전 키.
 *
 * 서버는 봉투에 code 와 한국어 message 를 함께 담아 보낸다. 여기 없는 코드는 서버가 준
 * 한국어를 그대로 띄운다 — 새 에러가 생겨도 화면이 비지 않고, 이 표에 한 줄 더하면
 * 그때부터 번역된다. 서버 Java 의 문구는 손대지 않는다.
 */
const BY_CODE: Record<string, string> = {
  'ITINERARY_NOT_FOUND': 'error.itinerary.notFound',
  'ITINERARY_FORBIDDEN': 'error.itinerary.forbidden',
  'ROUTE_TOO_FEW_POINTS': 'error.route.tooFewPoints',
};

/**
 * 사람에게 보여 줄 에러 문구 — 언어를 받는 순수 함수.
 *
 * 판단이 여기 있고 errorText() 는 스토어에서 언어만 꺼내 넘기는 껍데기다. 이렇게 갈라
 * 두어야 i18n-check.mjs 가 이 함수를 떼어내 node 로 돌려 볼 수 있다(스토어는 node 에
 * 없다). 본문에 타입 캐스트(`as …`)를 쓰지 않는 이유도 같다.
 */
export function errorTextIn(locale: Locale, err: ApiErrorBody): string {
  const key = err && err.code ? BY_CODE[err.code] : undefined;
  if (key) return translate(locale, key);
  return (err && err.message) || translate(locale, 'common.error.unknown');
}

/** 화면·인터셉터에서 쓰는 쪽. 현재 언어를 꺼내 위로 넘긴다. */
export function errorText(err: ApiErrorBody): string {
  return errorTextIn(useLocaleStore.getState().locale, err);
}
```
